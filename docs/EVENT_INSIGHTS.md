# Amazon Developer Hackathon 2026: event insights

**Checked:** 19 October 2026 against the live Devpost event page and the workspace copies in [`references/devpost/`](../references/devpost/). Event rules can change; the official rules control where event copy conflicts.

## Tracks and selected direction

The event has four primary tracks: Fire TV, Alexa+, Bee (Wearable AI), and Ring. The project direction is **Alexa+**, with TableReady framed as a household productivity experience. Alexa+ accepts a working self-hosted MCP server using Streamable HTTP and MCP version 2025-11-25 or later, or an Agent Skill. The event also permits a simulated Alexa+ web experience. TableReady implements a real local MCP server and browser client; it is not an Alexa+ device integration. Participants cannot access the gated Alexa+ partner tools, so the supported demo route is a self-hosted server and web client. [Hackathon overview](https://amazonappdev2026.devpost.com/), [FAQs](https://amazonappdev2026.devpost.com/details/faqs), [rules](https://amazonappdev2026.devpost.com/rules)

The mini challenges are **AWS Builder** and **Open Source**. TableReady uses no AWS services, so it does not claim AWS Builder eligibility. The Open Source prize requires an additional project or contribution made during the hackathon window; licensing the primary TableReady repository alone does not meet that separate requirement. [Rules](https://amazonappdev2026.devpost.com/rules)

## Judging

The rules first screen for basic viability and use of the required track technology. Advancing projects are judged equally on:

- **Tech implementation:** how well the project is built and uses the required track technology.
- **Design:** whether it feels like a complete, coherent experience with an intuitive interaction model.
- **Potential impact:** whether it makes a credible case for a customer need and could serve people beyond the event.
- **Quality of the idea:** whether the idea is creative and shows understanding of the ecosystem and user needs.

Optional friction-log entries can contribute a judging bonus of up to 10%. Keep entries factual and specific. [Judging criteria](https://amazonappdev2026.devpost.com/), [rules](https://amazonappdev2026.devpost.com/rules)

## Eligibility and teams

Entrants must be at least the legal age of majority where they live. Eligible entrants include individuals, teams of eligible individuals, and existing organizations. The rules set no team-size cap. Teams or organizations appoint one authorized representative to submit. Residents or organizations in restricted jurisdictions, and specified sponsor/administrator affiliates, staff, judges, and related parties, are excluded; review the complete rules for the full conditions. [Official rules](https://amazonappdev2026.devpost.com/rules), [FAQs](https://amazonappdev2026.devpost.com/details/faqs)

## Prize structure

The overview advertises $190,000 in combined cash and AWS-credit value. The rules list $138,000 cash plus AWS credits. Alexa+ track placements are:

| Placement | Award listed in the rules |
| --- | --- |
| 1st | $25,000 cash, $15,000 AWS credits, meeting with the Amazon Developer team, and project feature |
| 2nd | $15,000 cash, $5,000 AWS credits, and project feature |
| 3rd | $4,000 cash, $1,000 AWS credits, and project feature |

Each project can win at most one track prize and one mini-challenge prize. AWS credits were advertised as available while supplies lasted, but the Resources page says the codes ran out and requests stopped on October 7. Treat that update as the current availability status, despite the older October 21 cutoff text in the rules. ## Submission requirements

- A project description explaining what it does and how it works.
- A GitHub repository containing all source, assets, and setup/run instructions. It must be public with a detectable open-source license, or private and shared with Devpost and the named Amazon reviewers.
- For Alexa+, the repository must contain the required working MCP server or Agent Skill; a README mention alone is not enough. If using the simulation alternative, include its source and demonstrate it clearly.
- A public English YouTube or Vimeo demo video under three minutes. Lead with the user problem, show the project working, and call out the Alexa+ technology. Do not use unlicensed third-party media.
- Product feedback for every developer tool, API, and SDK used: purpose, what worked, what needs work, onboarding, and whether you would use it again. Keep this evidence-based; do not invent feedback.
- Selected track and mini-challenges, plus their extra fields if applicable. Explain significant changes made during the event if the project predates it.

Optional friction-log fields are: task, steps, expected result, actual result, severity, workaround, and suggested improvement. [Overview](https://amazonappdev2026.devpost.com/), [rules](https://amazonappdev2026.devpost.com/rules), [strong submission tips](https://amazonappdev2026.devpost.com/resources)
